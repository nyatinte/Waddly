## はじめる

WaddlyはApple Silicon搭載MacのmacOS 14以降に対応しています。安定版のHomebrew Caskは公式tapからインストールできます。

```sh
brew tap nyatinte/waddly
brew install --cask waddly
```

ベータ版 `0.1.0-beta.1` は安定版と別の `Waddly Beta.app` として試せます。

```sh
brew install --cask nyatinte/waddly/waddly-beta
```

安定版を更新するには `brew upgrade --cask waddly`、ベータ版は `brew upgrade --cask waddly-beta` を実行してください。ソースから試す場合は、開発者向けの[ビルド手順](CONTRIBUTING.md)を参照してください。

配布アプリは ad-hoc 署名で、公証していません。Gatekeeper が初回起動を止めた場合は、公式 GitHub Release から取得したことを確認し、Finder でアプリを Control キーを押しながらクリックして「開く」を選びます。Finder に「開く」が表示されない場合は、「システム設定 → プライバシーとセキュリティ → このまま開く」から許可してください。Gatekeeper を無効にしたり、隔離属性を削除したりしないでください。DMG を直接使う場合は、同じ Release にある `.sha256` ファイルでチェックサムを確認します。

初回起動時はセットアップウィザードで透過PNGの3×3スプライトシートを登録してください。キー入力に反応させるには、「システム設定 → プライバシーとセキュリティ → 入力監視」でWaddlyを許可してください。許可がなくてもアプリは起動できますが、キー入力には反応しません。画像の条件は「[自分のペットを使う](#自分のペットを使う)」に記載しています。

以前のベータ版で登録した画像が引き継がれずセットアップ画面が表示された場合は、スプライトシートを再登録してください。

## できること

ペットはキー入力に合わせて動きます。アプリが使うのは入力イベントが起きたことだけです。キーの内容やキーコードは保存しません。

待機中のペットは小さく呼吸し、ときどきまばたきします。メニューから呼吸アニメーションのON/OFFを切り替えられます。しばらくすると眠り、5分後にアニメーションが止まります。入力で復帰できるよう、入力監視は続けます。

ペットはデスクトップ上でドラッグでき、移動した位置は保存されます。表示サイズは「小・中・大」から選べます。

画面やメニューはmacOSの優先言語に合わせて日本語か英語で表示されます。それ以外の言語では英語を使います。メニューの「言語」の選択肢は、システム設定、日本語、Englishです。変更を反映するにはアプリを再起動してください。

Waddlyの表示先はDockとメニューバーの両方です。メニューの「表示先」で切り替えられ、少なくとも一方は表示されます。メニューバーのペンギンアイコンをクリックするか、ペットを右クリックするとメニューが開きます。サイズ、タイピング時の揺れ、画像、一時停止、ログイン時起動も設定できます。

一時停止中は時間による反応も停止します。画像を変更しても、再開するまでアニメーションは始まりません。

メニューバーには元のSVGを使った24 ptのペンギンアイコンだけを表示します。

初回起動時のセットアップウィザードでは、画像生成プロンプト、3×3 PNGの読み込み、入力監視の許可を案内します。画像ページ全体にPNGをドロップできます。画像を登録するまで次のページには進めません。ウィザードはメニューから再度開けます。

WaddlyはSwiftで作られたアプリです。使用するAPIはAppKit、Core Graphics、Core Animationです。外部ライブラリは使っていません。

## 自分のペットを使う

### ChatGPTで画像を作る

[ChatGPTを開き](https://chatgpt.com/)、使いたいペットの画像を添付してください。[日本語のプロンプト](prompts/ja.md)か[英語のプロンプト](prompts/en.md)をコピーして貼り付け、3×3のスプライトシートを作成します。プロンプトでは各コマの端に透明な余白を設け、絵やキーボードを境界まで詰め込まないよう指定しています。

### 画像の処理

初回セットアップでは、透過PNGの3×3スプライトシートを登録します。下の作例は、参照画像から9コマのシートを作り、アプリでコマごとに読み込む流れを示したものです。

| 参照画像 | 3×3スプライトシート |
| --- | --- |
| ![参照用のnyatinte-bot画像](assets/examples/nyatinte-bot.png) | ![nyatinte-botの3×3透過スプライトシート](assets/examples/nyatinte-bot-3x3.png) |

READMEに載せるため、参照画像は384 × 384 px、スプライトシートは768 × 768 pxに縮小しています。

読み込み時にはPNG形式で透過があることと、正方形で縦横のサイズが3で割り切れることを確認します。ファイルは20 MB以下、各辺は4096 px以下にしてください。シートを3×3に等分します。各コマの用途は、1・2コマ目が待機、3〜6コマ目がタイピング、7コマ目がEnter、8・9コマ目がスリープです。長辺が3072 pxを超えるシートは、分割前に3072 pxまで縮小します。

メニューの「画像設定…」では、待機・タイピング・スリープ・Enterの各行に透過PNGを複数追加できます。個別画像は読み込み時に長辺1024 pxまで縮小します。待機では1枚目を通常表示に使い、2枚目以降をまばたきの候補にします。タイピングとEnterの画像は順番に再生します。スリープの画像は順番に繰り返し、5分後に最後の画像で停止します。

画像はコマごとのPNGとして端末内のApplication Supportに保存され、次回起動時に復元されます。選択した元ファイルは変更せず、画像をネットワークへ送信しません。ペットの表示画像と作例画像はアプリ本体に同梱していません。アプリアイコンの画像だけを別途含めています。

以前のプロンプトで作成した画像は、コマの順番が異なる場合があります。Enter、うとうと、睡眠の反応を正しく割り当てるには、現在のプロンプトの順番を使ってください。

## プライバシー

Waddlyは読み取り専用の`CGEventTap`でキー入力イベントを監視します。アプリ内で使うのは、イベントのタイミングとEnterキーかどうかの判定だけです。入力文字列やキーコードの保存、ログ出力、ネットワーク送信は行いません。入力監視を許可しなくてもアプリは起動できます。

画像のデコードと保存はバックグラウンドで順番に処理します。プレビューは長辺480 pxまで縮小します。画像セットのメモリ見積もり（各フレームの画素バッファと128 KiBの余裕）に40 MiBの上限があります。上限を超える追加は保存せず、読み込みに失敗しても既存ファイルは削除しません。

## メモリ実測

メモリの目標は代表的な構成で物理フットプリント100 MB未満です。[再現可能な計測手順・実測基準・性能テスト](docs/MEMORY.md)を参照してください。ReleaseアプリのRSSと物理フットプリントを、起動・入力・大きな画像・繰り返しインポート・スリープ／静止状態で比較できます。`mise run memory:test`は別パッケージの回帰テストを実行します（Swift 6.2・macOS 26以降。本体はmacOS 14対応のままです）。

## 翻訳キーの追加

アプリの翻訳キーを追加・変更したら、`macos/ja.lproj/Localizable.strings`と`macos/en.lproj/Localizable.strings`の両方を更新してください。その後、リポジトリのルートで次のコマンドを実行してください。

```sh
swift Tools/generate_localizations.swift
```

生成スクリプトは両言語のキーが揃っているかを確認し、型安全なアクセサーを再生成します。`./macos/build.sh`では生成ファイルが最新かを検査します。
