## はじめる

Homebrew でのインストールは今後対応予定です。ソースから試す場合は、開発者向けの[ビルド手順](CONTRIBUTING.md)を参照してください。

初回起動時はセットアップウィザードに従って透過 3×3 PNG を登録します。キー入力に反応させるには、「システム設定 → プライバシーとセキュリティ → 入力監視」で Waddly を許可してください。許可がなくても起動しますが、キー入力には反応しません。画像形式の詳細は「[自分のペットを使う](#自分のペットを使う)」を参照してください。

## できること

- キー入力に合わせてペットが動きます。アプリはキーの内容やキーコードを保存せず、入力イベントの発生だけを使います。
- 待機中は小さく呼吸し、ときどきまばたきします。呼吸アニメーションはメニューから ON/OFF できます。しばらくすると睡眠し、5 分後にアニメーションを止めます。入力監視は復帰用に続きます。
- ペットはデスクトップ上でドラッグでき、位置を記憶します。表示サイズは「小・中・大」から選べます。
- UI は macOS の優先言語に合わせて日本語または英語で表示し、それ以外の言語では英語を使います。メニューの「言語」からシステム設定への追従、日本語、English を選べます。変更は再起動後に反映されます。
- Dock とメニューバーの両方に表示し、メニューの「表示先」から切り替えられます（どちらか一方は表示されます）。メニューバーの W アイコンまたはペットを右クリックするとメニューが開きます。サイズ、タイピング時の揺れ、画像、一時停止、ログイン時起動も設定できます。
- 初回起動時はセットアップウィザードが開き、画像生成プロンプト、3×3 PNG の読み込み、入力監視の許可を案内します。画像ページ全体に PNG をドロップでき、画像を登録するまで次へ進めません。メニューから再度開くこともできます。
- AppKit、Core Graphics、Core Animation を使った Swift アプリです。外部ライブラリは使っていません。

## 自分のペットを使う

### 画像の処理

初回セットアップでは、透過 PNG の 3×3 スプライトシートを登録します。下の作例は、参照画像から 9 コマのシートを作り、アプリがコマごとに読み込む流れを示しています。

| 参照画像 | 3×3スプライトシート |
| --- | --- |
| ![参照用のnyatinte-bot画像](assets/examples/nyatinte-bot.png) | ![nyatinte-botの3×3透過スプライトシート](assets/examples/nyatinte-bot-3x3.png) |

README 用に、参照画像は 384 × 384 px、スプライトシートは 768 × 768 px へ縮小しています。

読み込み時に PNG の形式、透過、正方形、3 で割り切れる縦横サイズを確認します。ファイルは 20 MB 以下、各辺は 4096 px 以下が必要です。シートは 3×3 に等分し、1・2 コマ目を待機、3〜6 コマ目をタイピング、7 コマ目を Enter、8・9 コマ目をスリープに割り当てます。長辺が 3072 px を超えるシートは、分割前に 3072 px まで縮小します。

メニューの「画像設定…」では、待機・タイピング・スリープ・Enter の各行に透過 PNG を複数追加できます。個別画像は読み込み時に長辺 1024 px まで縮小します。待機は 1 枚目を通常表示に使い、2 枚目以降をまばたき候補にします。タイピングと Enter は順番に再生し、スリープは順番に循環して、5 分後に最後の画像で停止します。

画像はコマごとの PNG として端末内の Application Support に保存され、次回起動時に復元されます。選択した元ファイルは変更せず、画像をネットワークへ送信しません。ペットとして表示する画像や作例画像はアプリ本体に同梱せず、アプリアイコン画像だけを別途含めます。

日本語・英語の生成プロンプトは[`prompts/ja.md`](prompts/ja.md)と[`prompts/en.md`](prompts/en.md)にあります。各コマの端には透明な余白を設け、絵やキーボードを境界まで詰め込まない指定です。

以前のプロンプトで作成した画像はコマの順番が異なる場合があります。Enter、うとうと、睡眠の反応を正しく割り当てるには、現在のプロンプトの順番を使ってください。

## プライバシー

Waddly は読み取り専用の `CGEventTap` でキー入力イベントを監視します。アプリ内で使うのは入力イベントのタイミングと Enter キーかどうかの判定だけです。入力文字列やキーコードの保存、ログ出力、ネットワーク送信は行いません。入力監視を許可しなくてもアプリは起動できます。

## メモリ実測

Apple Silicon 搭載 Mac、macOS 27.0、Release ビルドで測定しました。Waddly の起動約 13 秒後、待機アニメーション中の `ps` RSS は 52,176 KB（約 51 MiB）、`footprint` の物理メモリフットプリントは約 12 MB（ピーク約 13 MB）でした。プロセスや OS の状態で数値は変動します。タイピング中と、5 分以上静止させた状態は未計測です。

RSS には共有ライブラリなども含まれます。macOS のフットプリントはアプリが物理メモリに与える影響を見るための別指標です。どちらも、このプロジェクトの目標である 100 MB を下回る測定結果でした。

## 翻訳キーの追加

アプリの翻訳キーを追加・変更したら、`macos/ja.lproj/Localizable.strings` と `macos/en.lproj/Localizable.strings` の両方を更新し、リポジトリのルートで次を実行してください。

```sh
swift Tools/generate_localizations.swift
```

両言語のキーが揃っているか確認し、型安全なアクセサーを再生成します。`./macos/build.sh` は生成ファイルが最新かを検査します。
