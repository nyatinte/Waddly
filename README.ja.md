## Waddlyでできること

- キー入力に合わせてペットが動きます。入力した文字やキーコードは保存しません。
- 待機中は呼吸やまばたきをし、時間がたつと眠ります。キー入力で目を覚まします。
- ペットはデスクトップ上でドラッグでき、位置は次回起動時にも引き継がれます。
- 自分のペットの画像を登録できます。「アニメーション設定…」で待機やタイピングなどの動きを変更できます。
- メニューではサイズ、動き、表示先、言語を設定できます。「セットアップガイド…」では最初のペットの登録とキー入力への反応の有効化を案内します。言語の項目名は「Language / 言語」です。
- Dock のアイコンをクリックすると、画像未登録ならセットアップを開きます。登録済みの場合はペットを手前に表示するだけで、アニメーション設定はメニューから開きます。セットアップが開いている場合は、その画面を手前に表示します。

## 自分のペットを使う

### 画像を用意する

[ChatGPT](https://chatgpt.com/)にペットの画像を添付し、[日本語のプロンプト](prompts/ja.md)または[英語のプロンプト](prompts/en.md)を使って3×3のスプライトシートを作成できます。この方法を使うと、画像はChatGPTの利用規約とプライバシーポリシーに従ってChatGPTに送信されます。外部サービスを使わず、手作業でシートを作成することもできます。

セットアップは、先にペット、次に許可の順で進み、どの画面でも右側にペットのプレビューを表示します。最初のステップでは「ChatGPTで画像を作成」でプロンプトのコピーとChatGPTの起動をまとめて行うか、「PNGファイルを選択」で手元のシートを登録できます。ウィンドウへPNGを直接ドロップしてもかまいません。PNGを選んだ時点で登録されます（ファイルを選ぶまでは何も変わりません）。登録すると右側のプレビューで9コマすべての動きが繰り返し再生され、「アニメーション」と「9コマ」を切り替えたり、各ポーズを再生して確かめられます。ファイル選択をキャンセルした場合、登録済みの画像は変更しません。各コマは左上から順に、待機2枚、タイピング4枚、Enter 1枚、スリープ2枚です。

プレビューでは9コマを明るい背景と暗い背景の両方で表示できます。切り替えながら、各コマの端に隣のポーズの断片や浮いた不要なピクセルがないかを調べ、混入した点や断片だけを除去します。意図した効果線、睡眠の記号、Enterのきらめきは残してください。古い作例を登録済みの場合は、修正版のシートをダウンロードして再度読み込んでください。保存済みのコマは自動では更新されません。

### 画像の条件

- 透過PNGで、縦横が同じ長さの画像
- 縦横のピクセル数が3で割り切れること
- ファイルサイズは20 MB以下、各辺4096 px以下

長辺が3072 pxを超えるシートは、読み込み時に縮小します。メニューの「アニメーション設定…」から、各動作に複数の画像を追加することもできます。画像が多い場合は横にスクロールして編集できます。個別画像は長辺1024 pxまで縮小されます。

画像はコマごとのPNGとして端末内に保存されます。元ファイルは変更せず、画像をネットワークへ送信しません。以前のプロンプトで作成した画像はコマの順番が異なる場合があるため、現在のプロンプトを使ってください。

## はじめる

WaddlyはApple Silicon搭載MacのmacOS 14以降に対応しています。サードパーティのHomebrew tapから配布します。Homebrew 6.0以降ではサードパーティCaskを明示的に信頼する必要があります。以下のコマンドはインストールするCaskだけを信頼し、tap内の現在および将来の全パッケージやコマンドを信頼するものではありません。

```sh
brew tap nyatinte/waddly
brew trust --cask nyatinte/waddly/waddly
brew install --cask waddly
```

Caskへの信頼設定は今後の更新にも適用されます。取り消すには `brew untrust --cask nyatinte/waddly/waddly` を実行してください。

更新するには `brew upgrade --cask waddly` を実行してください。ソースから試す場合は、開発者向けの[ビルド手順](CONTRIBUTING.md)を参照してください。

配布アプリは ad-hoc 署名で、公証していません。Homebrew Caskはインストールと更新の後に隔離属性を削除するため、Homebrew経由ではGatekeeperの保護が弱まります。この処理はDeveloper ID署名や公証の代わりにはなりません。DMGを直接ダウンロードした場合は隔離属性が残るため、Gatekeeperが初回起動を止めることがあります。公式GitHub Releaseから取得したことを確認し、「システム設定 → プライバシーとセキュリティ → このまま開く」からアプリを許可してください。macOS 15以降ではControlキーを押しながらクリックして「開く」を選んでも警告を解除できません。[Appleの初回起動手順](https://support.apple.com/ja-jp/102445)を参照してください。DMGを直接使う場合は、同じReleaseにある `.sha256` ファイルでチェックサムを確認します。

初回起動時はセットアップガイドに沿って画像を登録してください。

### キー入力への反応を有効にする

2つ目のステップで「入力監視」の許可を求めます。Waddlyはシステム設定を開き、その隣に並び、自分のプレビューを案内図に変えます。アイコンを一覧へドラッグして、Waddlyをオンにしてください。ドロップできない場合は「別の方法で追加」から手順を確認できます。

![Waddlyを入力監視の一覧へドラッグする様子](assets/examples/input-monitoring-guide.gif)

macOSが許可を反映するのはアプリの再起動後です。Waddlyはセットアップの途中経過を覚えているので、次回起動時は最初からではなく同じ画面に戻ります。許可がなくてもアプリは起動できますが、キー入力には反応せず、その状態はメニューバーに表示されます。

## プライバシー

入力イベントはアニメーションの制御に使います。入力内容やキーコードを保存・記録・送信しません。画像は端末内に保存します。

## メモリ実測

メモリの目標は代表的な構成で物理フットプリント100 MB未満です。非常に大きなシート（例: 3072 × 3072・9コマ）の取り込みでは、現行リリースでこの目標を超えることがあります。これは1.0における既知の許容例外で、通常利用では100 MB未満を目標とします。[再現可能な計測手順・実測基準・性能テスト](docs/MEMORY.md)を参照してください。ReleaseアプリのRSSと物理フットプリントを、起動・入力・大きな画像・繰り返しインポート・スリープ／静止状態で比較できます。`mise run memory:test`は別パッケージの回帰テストを実行します（Swift 6.2・macOS 26以降。本体はmacOS 14対応のままです）。
