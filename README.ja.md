## Waddlyでできること

- 自分のペットの画像を登録できます。
- キー入力に合わせてペットが動きます。入力した文字やキーコードは保存しません。
- 待機中は呼吸やまばたきをし、時間がたつと眠ります。
- ペットはデスクトップ上でドラッグでき、好きな位置に配置できます。
- ペットはすべてのデスクトップ（Space）に表示されます。フルスクリーンアプリの上に強制表示はせず、ディスプレイの切断や構成変更のあとは見える位置に戻します。
- ペットを右クリックして「ペットをシェア」を選ぶと、5秒のMP4（384 × 384）と3×3のPNGスプライトシート（9コマ・取り込んだコマのサイズ）を端末内で作成します。カードには書き出したファイルのプレビューと形式を表示します。「動画をコピー」は動画ファイルをクリップボードへコピーするため、貼り付け先でファイルとして添付できます。「画像をコピー」ではスプライトシートをコピーします。どちらも成功・失敗を画面内に表示します。「Xでポストする」は「#ShareMyWaddly」だけが入った投稿画面を開き、文章とファイルの添付は自分で行います。作成に失敗した場合は「再試行」できます。シェア画面はmacOSのライト／ダーク表示に追従し、閉じると作成を中止します。シェア素材をファイル保存する機能はありません。[シェア機能のノート](docs/SHARE.md)に動作とQA上の制限を記載しています。

## はじめる

WaddlyはApple Silicon搭載MacのmacOS 14以降で動作します。インストール方法は2つです。

### Homebrewでインストール

今後の更新もHomebrewで行いたい場合に向いています。Homebrew 6.0以降ではサードパーティのCaskを明示的に信頼する必要があるため、次のコマンドで、インストールするCaskだけを信頼します。

```sh
brew tap nyatinte/waddly
brew trust --cask nyatinte/waddly/waddly
brew install --cask waddly
```

更新するには `brew upgrade --cask waddly` を実行します。信頼を取り消すには `brew untrust --cask nyatinte/waddly/waddly` を実行してください。

### GitHub Releasesからインストール

[最新リリース](https://github.com/nyatinte/Waddly/releases/latest)から `Waddly-<バージョン>-macos-arm64.dmg` をダウンロードして開き、Waddlyをアプリケーションフォルダへドラッグします。同じリリースにある `.sha256` でチェックサムを確認できます。

配布アプリはad-hoc署名で公証されていないため、初回起動時にGatekeeperが止めることがあります。「システム設定 → プライバシーとセキュリティ → このまま開く」で許可してください。macOS 15以降ではControlキーを押しながらの「開く」では解除できません。

ソースから試す場合は、開発者向けの[ビルド手順](CONTRIBUTING.md)を参照してください。

初回起動時はセットアップガイドに沿って画像を登録してください。

### キー入力への反応を有効にする

2つ目のステップで「入力監視」の許可を求めます。アイコンを一覧へドラッグして、Waddlyをオンにしてください。

許可しただけでは確認済みにはなりません。実際にキーを押してペットが反応すると「確認済み」になり、次のステップへ進めます。

![Waddlyを入力監視の一覧へドラッグする様子](assets/examples/input-monitoring-guide.gif)

macOSが許可を反映するのはアプリの再起動後です。

## 自分のペットを使う

### 画像を用意する

[ChatGPT](https://chatgpt.com/)などの画像生成サービスに[生成用プロンプト](prompts/ja.md)を送ると、3×3のスプライトシートを作成できます。

<details>
<summary>生成用プロンプトを表示</summary>

```text
作りたいキャラクター：＜ここに書き換える＞

この行が空欄か「＜ここに書き換える＞」のままの場合は、どんなペットやキャラクターを作りたいか、先にユーザーへ質問してください。

上記のキャラクターで、Waddly用の3×3アニメーションスプライトシートを作成してください。参考にしたい画像を添付している場合は、その画像の個体を描いてください。

【キャラクター】
- 個体の特徴（種類、色、模様、体型）を全コマで保つ。

【画風】
- 16-bit機のゲーム風のピクセルアート。色数は少なく、輪郭は太く、陰影は2〜3段階。
- ぼかし、アンチエイリアス、グラデーション、光彩、写真風の表現は使わない。
- 9コマで同じ大きさ、同じ向き、同じカメラ位置にする。キャラクターの頭の上端・体の下端・左右の中心を、9コマですべて同じ位置にそろえ、動きで変えない。

【シートと配置】
- 透過PNGを1枚だけ出力する。3×3の9コマ。セルは同じ大きさの正方形にし、辺の長さは3で割り切れる値にする。
- 背景は本物の透明にし、キャラクターの輪郭の外側はアルファ0にする。チェッカー柄、白、灰色、色付きの背景、グラデーション、地面、影は描かない。
- キャラクター全体を各セルの中央50%の範囲（四辺に25%ずつの余白）に収める。耳、しっぽ、羽、キーボード、エフェクトもすべて内側に置く。
- セルの境界や隣のセルに1ピクセルでも触れたセルは、不正な出力とみなす。
- 収まらない場合は、キャラクターを小さくするのではなく、ポーズやエフェクトを控えめにする。
- 枠線、区切り線、番号、説明文、ロゴ、透かしは描かない。Enterキーの記号以外の文字は入れない。

【9コマ：左上から右へ、上から下】
1. リラックスして座っている
2. 1コマ目と同じ姿勢でまばたきしている
3. 集中した表情でキーボードに向かっている
4. ゆっくりタイピングしている
5. 4コマ目と少し違う姿勢でタイピングしている
6. 前のめりになって速くタイピングしている
7. 大きなEnterキーを勢いよく押し込む瞬間。参考画像を添付している場合はその勢いを参考にする
8. まぶたが重く、うとうとしている
9. 丸くなって安心して眠っている

【キーボードとエフェクト】
- 3〜7コマ目にだけ、9コマで同じ形・同じ大きさの小さなキーボードを描く。幅はセル幅の40%以下にする。
- 7コマ目はEnterキーを他のキーより大きく描く。Enterキーもセル幅の30%以内に収める。「↵」の記号は付けてもよいが、「Enter」などの文字は書かない。
- 7コマ目の星形のきらめきと衝撃線は、体のすぐそばに置く。線は短いものを2本までにし、体の外側へセル幅の5%を超えて伸ばさない。先端はセルの右端と下端から30%以上内側に置く。

この条件に合うスプライトシート画像だけを出力してください。
```

</details>

- 手持ちの画像をもとに作る場合は、ペットやキャラクターの画像をプロンプトと一緒に送ってください。
- 画像がない場合は、「丸い体の小さなペンギン」のように、作りたいキャラクターを文章で指定してください。画像の添付は不要です。

### 画像の条件

- 透過PNGで、縦横が同じ長さの画像
- 縦横のピクセル数が3で割り切れること
- ファイルサイズは20 MB以下、各辺4096 px以下

AIが生成したシートは、プロンプトで位置を指定しても、コマごとにキャラクターの縦位置が少しずれる（ピッチのずれ）ことがあります。その場合は読み込む前に修正してください。修正した各ポーズを、同じ大きさの透過キャンバスにキャラクターの基準位置をそろえて配置し、正方形の等分割3×3シートにまとめるか、共通のキャラクター画面で動作ごとに個別の画像を追加します。「コマを個別に編集…」では、同じ下書きを使ってコマごとの編集ができます。Waddlyは3等分の位置で読み込み、自動の位置補正は行いません。輪郭の外接矩形でそろえると、眠っているポーズやエフェクトの位置がずれるためです。

長辺3072 pxを超えるシートは読み込み時に縮小され、個別画像は最大1024 pxになります。共通のキャラクター画面では、PNGファイルの選択、ウィンドウ全体へのドロップ、「クリップボードから貼り付け」（⌘V）が使えます。複数種類のファイルや非対応ファイルのドロップは画面内に理由を表示します。高度な編集では動作ごとに複数の画像を追加できます。コマ操作の読み上げ名にはポーズと位置を含め、最後の必須コマを削除できない理由や端のコマをそれ以上移動できない理由をホバー時のヘルプで説明します。「キャラクターを変更…」では元のシートがなくても、保存済みのコマ（独自の枚数を含む）をすぐにプレビューして編集できます。変更は適用するまで下書きのままです。

ペットを右クリックすると、サイズや動作、言語、表示先、ログイン時の起動を変更できます。設定完了後は「入力監視を設定…」から許可・状態確認・復旧の案内へ直接入り、「キャラクターを変更…」で画像を差し替えたり編集したりできます。ステータスメニューからも同じ操作ができます。初回・未完了時は引き続き「セットアップガイド…」を開きます。入力監視の設定ウィンドウには初回設定のステップではなく「閉じる」を表示し、キャラクター画像のドロップは受け付けず、保存済みのキャラクターと設定の進捗を変更しません。セットアップガイドで「PNGを選択」または「画像を変更」を選ぶと共通のキャラクター画面が開きます。選択、貼り付け、ドロップした画像は、保存せずに下書きとして確認できます。セットアップでは「続ける」を押すと一度だけ適用されます。「キャラクターを変更」ウィンドウでは「適用」で保存し、保存が成功した場合のみ閉じます。保存に失敗した場合は下書きを保持して再試行できます。適用が拒否された場合は保存失敗と区別して知らせ、下書きを保持します。変更した下書きのキャンセルやウィンドウを閉じる操作では、破棄の確認を表示します。共通画面の外へのウィンドウ全体ドロップは、従来どおり直接読み込みます。読み込みエラーは現在のセットアップステップ上部に、ChatGPTを開けなかった場合のエラーは操作ボタンの近くに表示します。ガイドを閉じたり、画面や方法を切り替えたり、別の画像の読み込みを始めたりした後に、古い読み込み処理のエラーが再表示されることはありません。ドラッグ中に外観が変わっても、読み込み先の枠の強調表示を保ちます。画像がまだない場合は「まずサンプルで試す」で同梱のサンプルをすぐに表示できます。サンプルも他のペットと同じくローカルに保存され、「画像を変更」でいつでも差し替えられます。「入力監視」のステップは、イベントタップが動作している状態で実際のキー入力がWaddlyに届いてから成功と表示します。許可しただけの状態は再起動の案内を、タップが動作していてもキー入力がまだ届いていない状態は「キー入力を待っています」と表示し、確認済みにはなりません。一時停止するとタップが止まるため、再開後は新しくキーを押すまで待機表示になります。初回の流れと手動確認の項目は[初回起動のジャーニーマップとQAタスク](docs/setup-first-run-journey.md)に、自動テストで確認済みの範囲は[セットアップの状態とQA一覧](docs/setup-wizard-qa.md)にまとめています。

画像はコマごとのPNGとして端末内に保存されます。元ファイルは変更せず、ネットワークへ送信しません。古いプロンプトで作成した画像はコマの順番が異なることがあるため、現在のプロンプトを使用してください。

Waddlyは保存した画像の一覧をマニフェストとして画像の隣に保存し、参照されなくなったコマだけを削除します。アプリがクラッシュや強制終了で中断した場合、次回起動時には最後に保存が完了した画像に戻り、保存が完了していないコマは破棄されます。マニフェストはアトミックに書き込みますがディスクへ同期しないため、電源断では直近の変更が失われるか、以前の画像に戻ることがあります。読み込めないマニフェストがある間は画像の編集をブロックし、その状態では画像を削除しません。同じ一覧は設定にも記録するため、旧バージョンへ戻しても画像を見つけられます。ただし複数バージョンの同時利用や、保存の合間に旧バージョンで画像を追加する使い方は完全には対応していません。その場合、現在のバージョンは追加された画像を残したまま、次に画像をインポートまたは保存するまで、自身が最後に保存したセットを表示します。

## プライバシー

入力イベントはアニメーションの制御に使います。入力内容やキーコードを保存・記録・送信しません。画像は端末内に保存します。シェア素材もダイアログを開いたときに端末内で作成し、Waddlyからアップロードしません。コピーとXへの投稿はユーザーの操作で行います。Xロゴまたはテキストから投稿画面を開けますが、素材の添付や投稿は自分で行います。投稿画面にはハッシュタグ「#ShareMyWaddly」だけが入力され、本文は空のままなので自分で書けます。動画はファイルとしてコピーされるため、Xの投稿欄やチャットへ貼り付けて添付できます。

## メモリ実測

通常の利用では、メモリの物理フットプリント100 MB未満を目標にしています。シェア画面の初回計測では、生成後の表示中が53.5 MB、閉じて30秒後が90.5 MB、生成時の一時ピークが105.0 MBでした。1回のみの計測なので、ピーク目標を満たすとはまだ判断していません。非常に大きなシート（例: 3072 × 3072・9コマ）の取り込みも100 MBを超えることがあります（1.0での既知の例外）。[再現可能な計測手順・実測基準・性能テスト](docs/MEMORY.md)を参照してください。`mise run memory:test`は別パッケージの回帰テストを実行します（Swift 6.2・macOS 26以降。本体はmacOS 14対応のままです）。

より長い隔離キャラクターライフサイクル計測には `WADDLY_PROFILE_CHARACTER_LIFECYCLE=1 WADDLY_PROFILE_CHARACTER_CYCLES=10 ./macos/profile-image-app.sh` を使います。一時アプリをad-hoc署名し、単調増加時計のサンプル時刻と完了を記録します。`WADDLY_PROFILE_IMAGE_FIXTURE` でコピーして使う入力画像も指定できます。詳細は上記の計測手順を参照してください。この計測だけで配布アプリのメモリ予算を満たすとは判断しません。

## コントリビュート

開発への参加方法は[CONTRIBUTING.md](CONTRIBUTING.md)を参照してください。`mise run test` はSwift Testingが完了を報告しないまま終了した実行を失敗として扱います。ガード自体の確認は `mise run test:guard` で実行できます。AppKitのアクションテストは疑似クリックのイベント追跡ループではなくtarget/actionを送出します。[途中終了の原因と最小再現](docs/test-runloop-early-exit.md)も参照してください。画面の入口、操作状態、手動QAチェックリストの監査結果は[UX操作監査](docs/ux-interaction-audit.md)にまとめています。
